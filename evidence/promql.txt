# DATAEKO Capstone — Phase 4 Observability (PromQL)

## 4.1 Why a Counter is wrong for in-flight requests
A Counter can only monotonically increase (or reset to zero on process restart), whereas in-flight requests concurrently increase when a request arrives and decrease when that request completes; representing active concurrency requires a Gauge which supports both increment and decrement operations.

## 4.5 Counter Disappearance & Alerting Behavior

### What rate() does when a counter stops existing
When the target stops running and scrapes fail, Prometheus marks the time series as stale after the lookback delta (~5 minutes); `rate()` needs at least two samples in its range window, so when no new data points arrive or the series disappears, `rate()` returns empty (no data / NaN), rather than returning zero.

### Why an alert on "error rate" would not have fired
An error rate alert typically computes `errors / total`. When the API stops completely, `total` requests drops to 0, causing `0 / 0` which yields NaN / no data rather than an elevated error percentage. Without an explicit `up == 0` or missing-series alert, the error rate alert never triggers because no requests (successful or failed) are being evaluated.
